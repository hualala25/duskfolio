# 精简与优化方案

> 目标：核心信息与功能不变，减少冗余、突出关键、理清动线、统一质感。
> 每条都给了「原文 → 改后」，可以直接照着改。改动落点都标了文件与行号。

## 一、诊断：冗余到底在哪

按「对访客的影响」排序，不是按代码量。

### 1. bio 在解释导航 —— 最重的一处

`profile/zh.ts:64`

> 网络与新媒体专业大二学生，方向是智能传播。**这个页面上放着我的课程作业和论文：左边一册是每门课的作业，右边一册是写过的论文，文件夹里是一份履历。**

三个问题叠在一起：

- **和 `role` 重复**。`role` 已经是「网络与新媒体 · 智能传播方向」，bio 把同一句话又说了一遍。
- **在解释目录**。目录就在下面一行：「课程作业 32 / 论文 12 / 学术履历 05」—— 已经说过了。
- **「左边…右边」是错的**。手机和平板上没有左右，只有切换。这句话在移动端是误导。

一句话占了三件事的位置，一件事都没说好。

### 2. 每件物品都写两段，一段是废话

`profile/zh.ts:79-161`，五件物品各有 `anecdote` + `story`：

| 物品 | anecdote（讲材质/尺寸） | story（讲来历） |
|---|---|---|
| 名帖 | 一张对折的棉浆纸名片，正面只有名字、方向，和一个小圆点。 | 名片是给自己印的，印完发现比作业还花时间。 |
| 履历 | 两页：一页写学业与竞赛，一页写项目、工具和技能。 | 写这份履历的时候才发现自己一年里做了不少事…… |
| 选题票 | 一张选题票：赛事、题目、赛区、截止时间，都印在一张 150 毫米的卡纸上。 | 改过七版题目，最后留下的是最笨的那一个…… |
| 照片 | 图书馆四楼靠窗的位置，19:40，天快黑了。 | 那天在改学年论文的第八页…… |
| 便笺 | 一筆箋是一种窄长的信纸，只写几行：比一封信短，比一条消息多一点心意。 | 这张便笺放在文件夹的最后，写给第一个把它抽出来的人。 |

**story 都好，anecdote 基本都在描述「这是什么纸、多少克」** —— 那是制作说明，不是内容。而且 specs 里又说了一遍（见下）。

### 3. specs 把 anecdote 说过的话再说一遍

`profile/zh.ts:81-85`（名帖）：

```ts
specs: [
  { k: "纸张", v: "600 克棉浆纸" },
  { k: "印刷", v: "活版，单色" },
  { k: "尺寸", v: "91 × 55 毫米，对折" },
]
```

anecdote 说「对折的棉浆纸名片」，specs 说「600 克棉浆纸」「91×55 对折」——**同一件事的三种说法**。

选题票更严重：specs 有「赛事 / 赛区 / 形式」，而 `ticket` 本身又有 `event / venue / talk` 字段，票面上已经印了。

### 4. 详情视图里两个字段是纯噪音

`AlbumDetail.tsx:221-231`，论文详情显示的规格行：

| 字段 | 现状 | 问题 |
|---|---|---|
| 载体 | `中国科技论文在线` 之类 | ✅ 有用 |
| 收录 | `2026 年 10 月 29 日` | ✅ 有用 |
| **作者** | `罗语墨` | ❌ 这是他自己的站，读者知道作者是谁 |
| **色值** | `#f0d3da` | ❌ 设计参数，读者不关心 |

### 5. 按钮文案同义词泛滥

`i18n.ts:238-274`：

- `readFull` = 「读全文」，`readFullShort` = 「读全文」—— **完全一样，纯冗余**
- `putBack` =「放回去」/ `putBackShort` =「放回」
- `close` / `closeAlbum` / `closeFolio` / `closeFolioShort` 四兄弟都是「合上」的变体
- `open` / `openFolio` / `openAlbum` / `openIt` 四个「打开」

视觉上应该只出现一种说法，完整的留给屏幕阅读器。

### 6. hint 与 handling 是两套并行文案

同一条操作说明维护了两份，内容几乎相同：

```
handling.cards  = 拖动页边或用方向键翻页。取出一张作业卡，可以看得更近。
hint.cards      = 滑动翻页，轻点卡片取出。
```

区别只是「拖 / 滑」「点 / 轻点」。两份都要改，容易改漏。

### 7. handling 有大半是文学，不是指引

`i18n.ts:232`

> 十二篇论文，十二个黄昏。翻过这一页，读它们的摘要。

这句很漂亮，但**它在用户还没成功翻过任何一页的时候出现**。人在找操作方法，得到的是诗。

## 二、内容方案

### 2.1 页面骨架（`profile/zh.ts` + `i18n.ts`）

| 位置 | 原文 | 改后 | 为什么 |
|---|---|---|---|
| `bio` | 网络与新媒体专业大二学生，方向是智能传播。这个页面上放着我的课程作业和论文：左边一册是每门课的作业，右边一册是写过的论文，文件夹里是一份履历。 | 关心媒介内容怎么被生产、怎么被算法接住，以及读者在其中还剩下多少主动性。 | 身份交给 `role`，结构交给目录，bio 只说「我在想什么」 |
| `handling.postcards` | 十二篇论文，十二个黄昏。翻过这一页，读它们的摘要。 | 拖动翻页，点开读摘要。 | 先教会动作，诗意留给论文标题 |
| `handling.cards` | 拖动页边或用方向键翻页。取出一张作业卡，可以看得更近。 | 拖动翻页，点开看作业。 | 一句话一个动作 |
| `handling.resume` | 倾斜桌面，袋里的东西会随之滑动。取出一件，就能细看。 | 倾斜桌面，或取出一件细看。 | 删掉解释「为什么」，只留「怎么做」 |
| `handling.closed` | 点一下封面，把它打开。 | 点封面打开。 | 去掉量词和「它」 |
| `hint.*` | 与 handling 平行的另一套 | **合并进 handling**，按设备只换动词（桌面「拖动 / 点开」，手机「滑动 / 轻点」） | 一处维护，不会改漏 |

> 合并后 `Dict.hint` 整个字段可以删掉，`Shell.tsx:770-775` 与 `:738` 统一读 `handling`。

### 2.2 五件物品：删 anecdote，压缩 story

`anecdote` 字段整体删除（`schema.ts` 里保留为可选，兼容旧数据），只留 `story`。story 做轻度压缩：

| 物品 | 改后 story |
|---|---|
| 名帖 | 名片是给自己印的，印完发现比作业还花时间。里面留给真正会回信的人。 |
| 履历 | 写这份履历的时候才发现自己一年里做了不少事，都散在文件夹里。整理出来，才算有了形状。 |
| 选题票 | 改过七版题目，最后留下的是最笨的那一个：把长征九十周年，交给一个具体的人来走。 |
| 照片 | 那天在改学年论文的第八页，改到一半抬头，窗外的天正好是这个颜色。就用它当了第一张。 |
| 便笺 | 这张便笺放在文件夹的最后，写给第一个把它抽出来的人。 |

照片的 `caption`（「图书馆，19:40」）已经担了画面感，story 里不用再重复时间地点。

### 2.3 specs：只留读者真正会看的

| 物品 | 删掉 | 留下 | 理由 |
|---|---|---|---|
| 名帖 | 纸张 / 印刷 / 尺寸 | 邮箱、主页、所在、语言（`inside` 那四条本来就有） | 工艺参数没人看，联系方式才有用 |
| 履历 | 页数 2 | 更新（2026 年 11 月）、语言 | 页数在翻动时自然知道 |
| 选题票 | 赛事 / 赛区 / 形式（三条全删） | —— | `event` / `venue` / `talk` 已印在票面上，重复 |
| 照片 | 无 | `place`、`date`（已有） | 保持 |
| 便笺 | 无 | 保持 | 保持 |

### 2.4 详情视图：删两个字段，收一组同义词

`AlbumDetail.tsx`

- 论文详情：删「作者」「色值」，只留 **载体 / 收录**
- 作业卡详情：删「类别：课程作业」（整册都是课程作业，标题已说明）
- 控制行文案收敛：

| 位置 | 现在 | 改后 |
|---|---|---|
| 主操作 | 读全文 / 读全文 | **读全文**（删 `readFullShort`，统一取 `readFull`；手机上也不缩写，三个字不占地方） |
| 次操作 | 翻面 / 翻回 | 保持 |
| 次操作 | 复制 #f0d3da | 保持（但仅在有图/色的卡片上出现） |
| 退出 | 放回去 / 放回 | 视觉统一 **放回**；`aria-label` 用「放回桌面」 |
| 关闭 | 合上 / 合上册子 / 合上文件夹 / 合上 | 视觉统一 **合上**；`aria-label` 按语境用完整版 |

### 2.5 resume 的 summary 与 bio 分工

现状两句几乎一字不差，同一句话印在页面和履历上。

```
bio     = 关心媒介内容怎么被生产、怎么被算法接住，以及读者在其中还剩下多少主动性。
summary = 网络与新媒体专业大二学生，智能传播方向。做过课程作业、学年论文和一次竞赛；
          关心的始终是同一件事——内容由谁生产，又落到谁手里。
```

一个说「我在想什么」，一个说「我做过什么」。

## 三、交互与动线

### 3.1 现在最大的动线问题：读正文要走三步

```
打开页面 → 点目录切到论文册 → 点卡片开详情 → 点「读全文」 → 才看到正文
```

**内容是访客最想要的东西，却排在第四步。**

改：**有正文的条目，打开详情即进正文。**

- 详情打开后 `reading` 默认 `true`
- 标题（`.doc-title`）在最上，下面是正文
- 控制行第一项变成「**回到卡片**」，第二项是「原文件 ↗」
- 想看图的人点一次就回去了

省一步，且「读」成为默认动作而非隐藏功能。

### 3.2 首屏：让人知道这册子能点

现状：`Shell.tsx:705` `showControls = folio && stage.ready && !next`，控件在 ready 后出现；但**册子本身可点这件事没有任何提示**，只有左下角一行小字。

改（三选一，建议 a + c）：

- **a. 一次轻推**：加载完成后 800ms，合着的册子封面抬起 6px 再落下（400ms，`ease-out`），只做一次，`prefers-reduced-motion` 下不做。
- **b. 目录反哺**：鼠标悬停目录项时，对应册子抬 3px 并投一层柔光（告诉用户「这两个是同一个东西」）。手机端忽略。
- **c. 控件常驻且极淡**：`.hands .ctl` 常驻 `opacity: .45`，悬停/聚焦升到 1。现在是 0 → 1 的硬切换，用户不碰就永远看不见。

### 3.3 目录与册子建立「同一物件」的线索

`Shell.tsx:203` 的 `.toc-disc` 现在是一个装饰圆点。

改：这个圆点填**对应册子的封面色**。

```
课程作业 ●  32   ← 桃 #e6b0a8
论文     ●  12   ← 樱 #e9bfc9
学术履历 ●   5   ← 臙脂 #8f2f43
```

一眼看出「这行字和桌上那本书是同一个」。零成本，效果直接。

### 3.4 详情视图：按钮按重要性分权重，而不是等宽排列

现在「读全文 / 翻面 / 复制 / 放回」四个同等权重的文字按钮并排。

改成三级：

| 层级 | 按钮 | 处理 |
|---|---|---|
| 主 | 读全文（或回到卡片） | 强调色 `--beni`，稍加字重 |
| 次 | 翻面 / 复制 | 墨色 `--tetsu`，常规字重 |
| 退出 | 放回 | `--koharu` 弱化色，靠最右，且有 `Sep` 隔开 |

「放回」是离开，不该和最想让人点的动作长得一样。

### 3.5 加载态：从「一个词」到「有进度」

现在只有一个 `正在打开文件夹` + 一条线。

改成分阶段（每阶段一句话，不编造百分比）：

```
正在取引擎 → 正在排版 → 正在上光
```

配合已有进度条（`.dawn` 的 `--p`）。2 秒内的正常网络下用户几乎看不到；慢网下至少知道在动。

### 3.6 反馈要即时

- 目录切换：现在有 `CrossFade`，但**册子的切换没有方向感**。加一个 120ms 的水平位移（新册子从切换方向的一个极短位移进入），让「换了一本」可感知。
- 复制色值：现在按钮文字变「已复制」，好。补一个 1.2s 后自动复原（现在似乎要保持到鼠标离开）。

## 四、视觉与细节

### 4.1 信息层级：名字不是主角，目录才是

现在竖排名牌是左侧最大的元素，目录偏小。但访客来是为了看内容。

- 名牌字号 **−15%**（`.id-name`）
- 目录字号 **+1 级**，行距 +2
- 目录项 hover 时出现一条 2px 的左侧短线（对齐用，不是描边）

目标：视线落点顺序变成 **目录 → 名牌 → bio → 说明**。

### 4.2 三本册子的封面色要能分辨

现在 `momo #e6b0a8`（桃）和 `sakura #e9bfc9`（樱）明度太接近，缩略图尺度下几乎一样。

建议拉开：

| 册子 | 现在 | 建议 | 理由 |
|---|---|---|---|
| 课程作业 | 桃 `#e6b0a8` | 桃 `#e0a096`（略深、略暖） | 和樱拉开 |
| 论文 | 樱 `#e9bfc9` | 樱 `#efd0d8`（更浅、更冷） | 最轻的一册，配"读" |
| 学术履历 | 臙脂 `#8f2f43` | 保持 | 已经足够深，是唯一的深色锚点 |

三本从浅到深的顺序，正好对应「翻得最多 → 最正式」。

### 4.3 左侧文字列分三组，组间距要大于组内

现在是五块等距堆叠，读起来像一列清单而不是三个段落。

```
┌ 名牌（名字 + 身份 + 时间）
│ bio
└ ─────────── 组间距 32
┌ 目录（三行）
└ ─────────── 组间距 24
┌ handling
│ 联系 / 语言 / 声音 / 文字版
└
```

组间距用 `margin-top` 而不是空隙，保证在短屏上也能压缩。

### 4.4 详情遮罩再透一点

`detail.css` 现在 `rgb(250 240 238 / .62)`。

改 `.55`。理由：这个站的空间感来自「书在桌上」，遮罩越实，桌面越消失，书就越像一张图。 `.55` 仍能保证文字对比（正文 8.3:1 的余量足够）。

### 4.5 正文排版：行宽收到 34 字

`detail.css` 的 `.doc-body { max-width: 38em }`。

中文正文的舒适行宽是 30–36 个汉字。38em 在 15.5px 下约 590px，一行约 38 字，偏宽。

改 `34em`（约 33–34 字/行），同时 `line-height` 从 30px 提到 31px。

### 4.6 统一圆角与阴影语言

现在详情里的纸张是 `border-radius: 2px`，按钮是文字，卡片是直角 —— 基本一致。但：

- `.doc-fig img` 用 `2px` 圆角 + 两层阴影，和 `.doc-sheet` 的阴影语言不同（一个 `--shadow-paper`，一个手写）。
- 建议：图统一用 `--shadow-snap`，与册子里的拍立得、明信片一致。

### 4.7 细节：删掉「复制色值」

如果卡片没有真实色值语义（现在色值是设计用的浅粉），这个按钮对访客没有意义。

建议：只在**论文卡**保留（那是天空的色），作业卡删除。

## 五、执行优先级

| 级别 | 内容 | 影响 | 改动量 |
|---|---|---|---|
| **P0** | bio 重写、删 anecdote、specs 精简、详情删「作者/色值」、按钮同义词收敛 | 删掉最多冗余，访客第一眼就清爽 | 只动 `profile/zh.ts` + `i18n.ts` + `AlbumDetail.tsx`，约 60 行 |

## 两处偏差

**1.「控件常驻极淡」没做 —— 方案里的诊断有误**

方案说 `.hands .ctl` 是 0 → 1 的硬切换、用户不碰就看不见。实际读代码后发现：
`showControls = folio && stage.ready && !next`，引擎 ready 后控件**自动显示**，不存在「看不见」的问题。
所以这条取消，没有保留的必要。

**2.「首屏轻推」「加载分阶段」「册子切换位移」没做**

这三项都要动 3D 引擎（封面抬起是场景里的变换，不是 DOM 动画），风险大于收益；
而且都是体感项，必须在真机上看才知道快慢。方案里本来就标了 P2「需真机调」。

如果之后想要，最稳的做法是纯 DOM 层的一次提示：加载完成后给 handling 那行字做一次 2px 上移淡入，
不碰引擎。现有的 `CrossFade` 已经有 300ms 渐变了，加位移是几行 CSS。

## 一个踩到的坑（值得记）

`.w.primary` 最初写成 `.ctl > .w.primary`，样式不生效 —— 因为**详情视图的 controls 外面套着一层
分组容器 `.cg`**，`.ctl > .w` 匹配不到直接子元素。底部的工具栏（`.hands`）才是 `.ctl > .w` 的结构。
改成不带父选择器的 `.w.primary` 才对。

排查方法：在浏览器里遍历 `document.styleSheets`，找出所有 `matches()` 该元素、且带 `color` 的规则 ——
一眼就能看出哪条没匹配上。
